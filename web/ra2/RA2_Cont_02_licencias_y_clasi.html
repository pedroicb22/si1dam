Teoría Técnica Bloque 02

✨ Clasificación y Marco Legal de los SO

Análisis de la diversidad de sistemas operativos actuales y el estudio de los contratos legales (licencias) que regulan su uso, distribución y modificación.

Clasificación de los Sistemas Operativos

Sistemas Propietarios

Sistemas cuyo código fuente es secreto y el usuario adquiere un derecho de uso, no la propiedad del programa.

  • Windows: Dominio en escritorio y empresarial. Arquitectura NT.
  • macOS: Basado en Unix (BSD), optimizado para hardware Apple.

Sistemas Libres / Open Source

Sistemas donde el código fuente es público, permitiendo su estudio, modificación y redistribución.

  • GNU/Linux: Múltiples distribuciones (Ubuntu, Debian, Fedora).
  • BSD: Alta estabilidad, muy común en servidores y firewalls.

Marco Legal: Tipos de Licencias

Tipo de Licencia Características Principales Ejemplo Típico
EULA (Proprietaria) Contrato de "Licencia de Usuario Final". Prohíbe la ingeniería inversa y la redistribución. Microsoft Office / Windows
GPL (General Public License) Garantiza las 4 libertades. Si se modifica y redistribuye, la nueva versión debe ser también libre. Kernel de Linux
MIT / Apache (Permisivas) Permiten el uso del código en proyectos propietarios sin obligar a liberar el código derivado. Diversas librerías de JS / Python
Suscripción (SaaS) Pago recurrente por el derecho de uso. El software suele estar en la nube o requiere validación online. Adobe Creative Cloud

Concepto de Copyleft

Es una estrategia legal que utiliza las leyes de copyright para asegurar que el software siga siendo libre. La regla fundamental es: "Puedes hacer lo que quieras con este programa, siempre y cuando compartas tus mejoras bajo la misma licencia".

Evita que el software libre sea "cerrado" por una empresa que cree una versión mejorada y la venda como propietaria.

Licencias Permisivas

A diferencia del copyleft, las licencias permisivas (como MIT) solo piden que se reconozca la autoría original. No obligan a que las obras derivadas sean libres.

Son muy atractivas para las empresas porque pueden integrar código libre en productos comerciales cerrados sin riesgos legales.

Análisis Comparativo: Coste vs. Flexibilidad

Modelo Propietario

Soporte técnico oficial, mayor compatibilidad con software comercial, pero coste de licencia elevado y dependencia del proveedor (Vendor Lock-in).

Modelo Libre

Coste 0, total control sobre la seguridad y personalización, pero requiere mayor curva de aprendizaje y soporte basado en la comunidad.

Modelo Híbrido

Empresas que venden soporte y servicios sobre software libre (Ej: Red Hat). Combinan la libertad del código con la seguridad de un contrato profesional.
