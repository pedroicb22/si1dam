✨ Planificación y Proceso de Instalación

Guía técnica sobre la preparación del entorno de hardware, la gestión de tablas de particiones y el despliegue de sistemas operativos desde diversos soportes.

Análisis de Requisitos y Firmware

Antes de cualquier instalación, es imperativo analizar la compatibilidad del hardware con la versión del SO. No se trata solo de "cumplir" los mínimos, sino de asegurar la estabilidad del sistema.

Requisitos Mínimos: El SO arranca, pero el rendimiento es insuficiente para tareas reales.
Requisitos Recomendados: El SO opera con fluidez, permitiendo multitarea y optimización de recursos.

BIOS vs UEFI

BIOS (Basic Input/Output System): Legacy. Basado en texto, limitado a discos de 2TB y particiones MBR.
UEFI (Unified Extensible Firmware Interface): Moderno. Soporta GUI, Secure Boot, arranque rápido y discos > 2TB mediante GPT.

Estructura de Disco: MBR vs GPT

Característica MBR (Master Boot Record) GPT (GUID Partition Table)
Límite de capacidad Máximo 2 TB Hasta 9.4 Zettabytes (ZB)
Número de particiones 4 Primarias (máx) Casi ilimitadas (128 en Windows)
Redundancia Copia única al inicio del disco Copia al inicio y al final (Autorreparable)
Compatibilidad Cualquier PC (Incluso muy antiguos) Requiere UEFI

Soportes de Instalación

  • USB Booteable: Herramientas como Rufus o Ventoy para crear medios de arranque.
  • PXE (Preboot Execution Environment): Instalación a través de la red local, ideal para despliegues masivos en empresas.
  • ISO Virtualizada: Montaje directo en hipervisores (VirtualBox, VMware).

Sistemas de Archivos (FS)

  • NTFS: Estándar de Windows. Soporta permisos y archivos grandes.
  • EXT4: Estándar de Linux. Optimizado para rendimiento y estabilidad.
  • Btrfs / ZFS: Modernos, con soporte nativo para snapshots y gestión de volúmenes.

Gestores de Arranque (Bootloaders)

El gestor de arranque es la primera pieza de software que se ejecuta tras el firmware. Su función es cargar el núcleo del SO en la RAM.

GRUB

El estándar en Linux. Muy flexible, permite el "Dual Boot" y carga kernels personalizados.

Windows Boot Manager

Gestor propietario de Microsoft. Integrado profundamente en la arquitectura UEFI.

Clover / OpenCore

Gestores avanzados utilizados frecuentemente para Hackintosh o sistemas con configuraciones complejas.
