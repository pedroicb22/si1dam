Tema 1: Administración de Usuarios y Grupos

Control de identidades, gestión de privilegios y políticas de acceso para garantizar la seguridad del entorno operativo.

1.1. Gestión de Identidades

Tipos de Cuentas de Usuario

Un sistema operativo no trata a todos los usuarios por igual. Dependiendo de la función, las cuentas se dividen en categorías para evitar que un fallo o un ataque comprometa la totalidad del sistema.

Cuentas de Administrador: Poder total sobre el SO. ROOT / ADMIN
Cuentas Locales: Usuarios personales con permisos limitados. USER
Cuentas de Sistema: Cuentas creadas para ejecutar servicios (daemons). SERVICE
Usuarios de Dominio: Identidades centralizadas (Active Directory). DOMAIN

Gestión de Grupos y Jerarquías

Asignar permisos usuario por usuario es ineficiente y propenso a errores. La solución profesional es la Gestión Basada en Grupos: se asignan permisos al grupo y los usuarios heredan esos derechos al pertenecer a él.

Grupos y Asignaciones

  • Creación: Agrupa usuarios con funciones similares (ej. "Soporte", "Contabilidad").
  • Asignación: Un usuario puede pertenecer a múltiples grupos simultáneamente.
  • Grupos Anidados: Un grupo puede ser miembro de otro grupo, creando una jerarquía de permisos.

1.2. Seguridad de Acceso

Políticas de Contraseñas

Para evitar ataques de diccionario o fuerza bruta, los administradores implementan directivas estrictas sobre las claves de acceso.

✕ Complejidad: Obligar al uso de mayúsculas, números y símbolos.
🕒 Tiempo de vida: Forzar el cambio de contraseña cada X días.
🔒 Bloqueo de cuenta: Deshabilitar el acceso tras N intentos fallidos.

Autenticación Multifactor (MFA)

El MFA añade capas de seguridad adicionales basándose en tres factores de autenticación:

1. Something you know: Contraseña o PIN.
2. Something you have: Token físico, Smartphone (App) o Smartcard.
3. Something you are: Biometría (Huella, Iris, Reconocimiento Facial).

Resumen Administrator Insight

  • El principio de Mínimo Privilegio dicta que un usuario solo debe tener los permisos estrictamente necesarios para su función.
  • Utilizar la cuenta de Root/Administrator para tareas cotidianas es un error crítico de seguridad; se deben usar herramientas como sudo o "Ejecutar como Administrador".
  • El MFA es la defensa más efectiva contra la suplantación de identidad en entornos de servidor.
